# 여의도 화랑아파트 일조권 분석 – QGIS 파일 추출 가이드

대교아파트 신축안 폴리곤(위치 보정 완료)을 기준으로, **화랑아파트**를 수광(受光) 대상으로
하는 일조권 분석에 필요한 파일을 QGIS에서 확보·추출하는 절차입니다.

---

## 0. 먼저 확인한 기하 관계 — 반드시 읽으십시오

작업을 시작하기 전에 방위 관계를 먼저 계산했습니다. 결과가 통상적인 예상과 다릅니다.

```bash
python3 daegyo_site_polygons.py --sun-table
```

### 대지 중심에서 본 주변 건물과 영향 시간대

| 건물 | 방위각 | 방향 | 거리 | 그림자 영향 시간대 |
| --- | ---: | :---: | ---: | --- |

### 결론

**화랑아파트는 대교아파트 신축 부지의 정동(방위각 94°)에 있습니다.**
동지일 그림자는 오전에 북서(312°), 정오에 북(360°), 오후에 북동(48°) 방향으로만 지며,
**동쪽으로는 지지 않습니다.** 그림자가 동쪽(94°)으로 지려면 태양이 서쪽 방위 274°에
있어야 하는데, 서울의 동지일 일몰 방위는 약 238°입니다.

> **즉, 대교아파트 신축이 화랑아파트 일조에 미치는 영향은 원리적으로 발생하기 어렵습니다.**
> 오히려 방위상 **화랑아파트(동측)가 대교아파트 신축의 오전 일조를 가리는** 관계입니다.

### 다만 아래 세 가지는 반드시 실제 데이터로 확인하십시오

1. **화랑아파트 위치가 개략값입니다.** 위 방위각은 배치도에 참고 표기된 사각형 기준입니다.
   화랑아파트 단지 실제 범위가 **북동쪽(방위 40~60°)까지 걸쳐 있다면**
   15:30~17:00 사이 늦은 오후에 영향이 생길 수 있습니다(그림자 길이 400~700 m).
2. **화랑아파트도 재건축을 추진 중입니다.** 현재 10층·3개동(1977년 준공, 160세대,
   여의도동 40-4)이지만, 소규모재건축으로 **최고 46층·2개동·264가구**(대지면적 9,395㎡)
   계획이 알려져 있습니다. **현황 기준인지 재건축 후 기준인지 전제를 먼저 정하십시오.**
3. **인접 대지 경계선 기준 높이제한** 검토는 그림자와 별개입니다.
   대교 신축이 화랑아파트 쪽 대지경계선에서 얼마나 이격·후퇴하는지는
   「건축법 시행령」 제86조와 서울시 건축조례로 별도 확인이 필요합니다.

**따라서 아래 절차로 화랑아파트 실제 건물 데이터를 받아 검증하는 것이 맞습니다.**

## 1. 화랑아파트 건물 데이터 내려받기

배치도에 있는 참고용 사각형이 아니라, **실측 기반 공공데이터**를 쓰십시오.

| 출처 | 받는 곳 | 특징 |
| --- | --- | --- |
| **GIS건물통합정보** (권장) | 국가공간정보포털 `nsdi.go.kr` → `오픈마켓` → `건물통합정보` 검색 | 건물 외곽선 + 건물명 + 지상/지하 층수. 시군구 단위 SHP |
| **브이월드 건물** | `vworld.kr` → `데이터` → `건물` | 3D 건물(높이 포함). 오픈API 키 필요 |
| **도로명주소 건물DB** | `business.juso.go.kr` (주소기반산업지원서비스) | 건물 외곽선 + 도로명주소. 무료 회원가입 |
| **서울 열린데이터광장** | `data.seoul.go.kr` | 서울시 한정 건물/지적 자료 |

**받을 범위**: `서울특별시 영등포구` 단위로 받으면 됩니다. 압축을 풀면
`.shp` / `.shx` / `.dbf` / `.prj` 파일이 세트로 나옵니다. **네 개를 같은 폴더에 두십시오.**

## 2. QGIS에 불러오기 — 인코딩이 핵심

1. 메뉴 **`Layer`** → **`Add Layer`** → **`Add Vector Layer…`** (`Ctrl+Shift+V`)
2. `Vector Dataset(s)` 에서 **`.shp`** 파일 선택
3. **⚠ `Encoding` 을 `EUC-KR` 또는 `CP949` 로 지정** — 공공데이터 SHP는 대부분
   CP949입니다. `UTF-8`로 두면 건물명이 `???` 로 깨져 4단계에서 검색이 안 됩니다
4. **`Add`** → **`Close`**

**이미 불러왔는데 깨졌다면**: 레이어 더블클릭 → `Source` 탭 → `Data source encoding`
을 `EUC-KR` 로 바꾸고 `OK`.

**좌표계 확인**: 레이어 더블클릭 → `Information` 탭에서 CRS를 봅니다.
`EPSG:5186`이 아니면(예: 5174, 5179), 그대로 두어도 QGIS가 자동 변환해 표시합니다.
다만 **내보낼 때는 반드시 EPSG:5186으로 통일**하십시오(5단계).

## 3. 대상 구역만 남기기 (1차 추출)

영등포구 전체는 수만 개 건물이라 무겁습니다. 관심 영역만 잘라냅니다.

### 3-1. 관심 영역 사각형 만들기

1. 메뉴 **`Processing`** → **`Toolbox`** → 검색창에 **`Create grid`** … 대신 더 쉬운 방법:
2. 지도를 대교~화랑 일대가 보이게 맞춘 뒤
3. **`Processing → Toolbox`** → **`Extract/clip by extent`** 검색 →
   **`Extract/clip by extent`** 더블클릭

### 3-2. 잘라내기

| 항목 | 입력값 |
| --- | --- |
| Input layer | 건물통합정보 레이어 |
| Extent | 오른쪽 **`…`** → **`Use Current Map Canvas Extent`** |
| Clipped (extent) | `[Save to File…]` → `hwarang_area.gpkg` |

**`Run`** → 대상지 주변 건물만 남은 레이어가 생깁니다.

## 4. 화랑아파트만 골라내기 (2차 추출)

### 방법 ① 건물명으로 필터 — 가장 확실

1. `Layers` 패널에서 잘라낸 레이어 **오른쪽 클릭** → **`Filter…`**
2. 열린 `Query Builder` 창에서
   - 왼쪽 `Fields` 목록에서 건물명 필드를 찾아 더블클릭
     (자료마다 이름이 다릅니다: `BLD_NM`, `BULD_NM`, `GRO_BLD_NM` 등 —
     **`All` 버튼을 눌러 값 목록을 보면 어느 필드인지 바로 압니다**)
   - 아래 표현식 칸에 입력:
     ```sql
     "BLD_NM" LIKE '%화랑%'
     ```
3. **`Test`** 로 몇 건인지 확인 → **`OK`**
4. 지도에 화랑아파트 3개 동만 남습니다

> 건물명이 비어 있으면 **지번으로** 거르십시오: `"지번필드" LIKE '40-4%'`
> (화랑아파트 지번: 서울 영등포구 **여의도동 40-4**)

### 방법 ② 화면에서 직접 선택 — 필드명을 모를 때

1. 툴바의 **`Select Features by area or single click`** 아이콘 클릭
2. `Shift` 를 누른 채 화랑아파트 동들을 하나씩 클릭 (선택되면 노란색)
3. 레이어 오른쪽 클릭 → **`Export`** → **`Save Selected Features As…`**

### 방법 ③ 위치로 추출 — 대지경계선 안의 건물만

1. **`Processing → Toolbox`** → **`Extract by location`**
2. | 항목 | 입력값 |
   | --- | --- |
   | Extract features from | 건물 레이어 |
   | Where the features (geometric predicate) | `intersect` |
   | By comparing to the features from | 화랑아파트 대지 폴리곤 |

## 5. 높이 필드 만들기 — 분석의 필수 입력

건물통합정보에는 층수는 있어도 **높이(m)가 없는 경우가 많습니다.** 직접 만듭니다.

1. 화랑아파트 레이어 오른쪽 클릭 → **`Open Attribute Table`**
2. 상단 **주판 모양 아이콘**(`Open Field Calculator`, `Ctrl+I`) 클릭
3. 입력

   | 항목 | 입력값 |
   | --- | --- |
   | ☑ Create a new field | 체크 |
   | Output field name | `height_m` |
   | Output field type | `Decimal number (real)` |
   | Expression | `"GRO_FLO_CO" * 2.8` |

4. **`OK`** → 연필 아이콘(`Toggle Editing`) 을 눌러 **저장**

**층고 기준값**

| 구분 | 층고 | 비고 |
| --- | ---: | --- |
| 1970~80년대 아파트 (화랑아파트 등) | **2.8 m** | 화랑아파트 10층 → 약 28 m + 옥탑 3 m |
| 최근 초고층 아파트 (대교 신축) | 2.95 m | 이미 반영됨 |
| 근린생활시설 | 4.0~4.5 m | |

**지반고(EL)도 함께 넣으십시오.** 같은 방법으로 `base_elev_m` 필드를 만들고
대교 대지와 같은 `13.3` 을 넣으면 두 단지를 같은 기준면에서 비교할 수 있습니다.
(정밀히 하려면 국토지리정보원 수치표고모델(DEM)에서 지점별 표고를 추출하십시오)

## 6. ★ 파일로 내보내기 (핵심 단계)

1. 화랑아파트 레이어 **오른쪽 클릭** → **`Export`** → **`Save Features As…`**
2. 아래처럼 설정

   | 항목 | 입력값 | 이유 |
   | --- | --- | --- |
   | **Format** | `GeoJSON` 또는 `GeoPackage` | 대교 폴리곤과 형식을 맞춤 |
   | **File name** | `hwarang_buildings.geojson` | |
   | **CRS** | **`EPSG:5186`** | ⚠ 대교 폴리곤과 동일하게. 다르면 겹치지 않음 |
   | **Encoding** | `UTF-8` | 내보낼 때는 UTF-8 |
   | ☑ Add saved file to map | 체크 | 바로 확인용 |

3. **`OK`**

> **선택된 것만 내보내려면** 위 대화상자에서 **`Save only selected features`** 를 체크하십시오.

### 형식 선택 가이드

| 목적 | 권장 형식 |
| --- | --- |
| 대교 폴리곤과 함께 쓰기 | **GeoJSON** (지금까지 만든 파일과 동일) |
| 여러 레이어를 한 파일로 | **GeoPackage(.gpkg)** |
| 타 프로그램(CAD, 감정평가 프로그램) 전달 | **ESRI Shapefile** — 단, 한글 필드명이 잘리므로 영문 필드명 사용 |
| 엑셀에서 수치만 보기 | **CSV** (아래 8-2 참조) |

## 7. 분석용 통합 레이어 만들기

그림자는 **모든 건물이 함께 있어야** 제대로 계산됩니다.
대교 신축 + 화랑아파트 + 기타 주변 건물을 하나로 합칩니다.

1. 메뉴 **`Vector`** → **`Data Management Tools`** → **`Merge Vector Layers…`**
2. `Input layers` 의 **`…`** → 아래 세 개 체크
   - `daegyo_buildings_epsg5186` (대교 신축 — 차폐물)
   - `hwarang_buildings` (화랑아파트 — 수광 대상)
   - 필요 시 주변 기존 건물
3. `Destination CRS` : **`EPSG:5186`**
4. `Merged` : `[Save to File…]` → `analysis_buildings.gpkg`
5. **`Run`**

> **주의**: 합친 레이어의 `height_m` 필드가 모든 건물에 채워져 있어야 합니다.
> 속성 테이블에서 `NULL` 이 있으면 그 건물은 그림자를 만들지 않습니다.

## 8. 분석 결과 파일 추출

### 8-1. 건물 높이 래스터(DSM) 만들기 → GeoTIFF

1. **`Processing → Toolbox`** → **`Rasterize (vector to raster)`**
2. | 항목 | 입력값 |
   | --- | --- |
   | Input layer | `analysis_buildings` |
   | Field to use for a burn-in value | **`height_m`** |
   | Output raster size units | `Georeferenced units` |
   | Horizontal / Vertical resolution | `1` (1 m 격자) |
   | Output extent | 대교 + 화랑이 모두 들어가도록 |
   | Rasterized | `[Save to File…]` → `dsm_1m.tif` |
3. **`Run`**

### 8-2. 일조시간 계산 → 래스터 + CSV

1. **`Plugins → Manage and Install Plugins…`** 에서 **`UMEP for Processing`** 설치
2. **`Processing → Toolbox`** → **`UMEP → Solar Radiation → Shadow Generator`**
3. 입력: `dsm_1m.tif`, 날짜 `2026-12-22`, 시간 간격 `30분`
4. 시간대별 그림자 래스터가 생성됩니다
5. 합산: **`Raster → Raster Calculator`** 로 그림자가 아닌 시간을 더하면 **일조시간 지도**

**결과 내보내기**
- 래스터: 레이어 오른쪽 클릭 → **`Export`** → **`Save As…`** → `GeoTIFF`
- 수치표: 레이어 오른쪽 클릭 → **`Export`** → **`Save Features As…`** →
  Format `Comma Separated Value (CSV)`, Encoding `UTF-8` → 엑셀에서 열람

### 8-3. 그림자 경계를 폴리곤으로 → 도면에 쓰기 좋음

1. **`Raster`** → **`Conversion`** → **`Polygonize (Raster to Vector)`**
2. 입력: 그림자 래스터 → 출력: `shadow_0900.geojson`
3. 시각별로 반복하면 **09:00 / 12:30 / 15:00 그림자 중첩도**를 만들 수 있습니다

### 8-4. 화랑아파트 창면 일조시간 — 실제 감정 방식

일조권 판단은 원칙적으로 **각 세대 거실 창면**에서 봅니다.

1. 화랑아파트 레이어 → **`Processing → Toolbox`** → **`Polygons to lines`**
2. 결과에서 **남향 면**만 선택 (대교 방향인 서측 면도 함께)
3. **`Processing → Toolbox`** → **`Points along geometry`**
   - `Distance` : `3` (3 m 간격 = 세대 폭 정도)
4. 생성된 점에 **층별 높이** 부여: `Field Calculator` 로
   ```
   13.3 + (층번호 - 1) * 2.8 + 1.2
   ```
   (지반고 + 층 바닥 + 창 중심 높이 1.2 m)
5. 이 점 레이어를 UMEP 또는 그림자 래스터에 겹쳐
   **`Processing → Raster analysis → Sample raster values`** 로 각 점의 일조시간 추출
6. **`Export → Save Features As…`** → CSV → 세대별·층별 일조시간 표 완성

### 8-5. 도면·이미지로 출력

| 결과물 | 방법 |
| --- | --- |
| **PDF 도면** | `Project → New Print Layout` → 이름 입력 → `Add Item → Add Map` → 범례·축척 추가 → `Layout → Export as PDF…` |
| **이미지(PNG)** | 같은 레이아웃에서 `Layout → Export as Image…` |
| **3D 화면 캡처** | 3D 맵뷰 상단 **카메라 아이콘** (`Save as Image`) |
| **좌표 포함 이미지** | `Project → Import/Export → Export Map to Image…` → ☑ `Append georeference information` |
