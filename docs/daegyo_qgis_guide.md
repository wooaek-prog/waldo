# 여의도 대교아파트 신축안 – QGIS 일조권 분석용 건물 폴리곤 생성 가이드

첨부된 **단지배치도**(축척 1/1000, A1 1/500)와 **사업시행계획인가 제원**을 근거로,
QGIS에서 바로 쓸 수 있는 건물 폴리곤(높이 속성 포함)을 생성하는 절차를 정리한 문서입니다.

> **파이썬·QGIS를 처음 쓰신다면** 이 문서 대신
> **[초보자 상세 매뉴얼](daegyo_beginner_manual.md)** 을 먼저 보십시오.
> 설치부터 메뉴 클릭 단위로 설명하며, 파이썬 없이 QGIS만으로 하는 방법도 담겨 있습니다.
> 이 문서는 옵션과 절차를 압축해 정리한 실무용 요약입니다.
>
> **인접 화랑아파트를 수광 대상으로 하는 분석**은
> **[화랑아파트 일조권 분석 – 파일 추출 가이드](hwarang_sunlight_analysis.md)** 를 보십시오.

## 2. 실행 방법

```bash
pip install pyproj shapely
python3 daegyo_site_polygons.py                       # 기본값으로 생성
python3 daegyo_site_polygons.py --outdir outputs/daegyo --epsg 5186
```

주요 옵션

| 옵션 | 설명 |
| --- | --- |
| `--config` | 배치도 트레이싱 정의 JSON (기본 `data/daegyo_site_plan.json`) |
| `--outdir` | 출력 폴더 (기본 `outputs/daegyo`) |
| `--epsg` | 출력 투영좌표계 (기본 5186 = Korea 2000 중부원점, 단위 m) |
| `--plan-up-azimuth` | 배치도 위쪽 방향의 진북 방위각(도). 기본 51.2051° (실측 보정값) |
| `--keep-area-scale` | 기준점에서 회전·위치만 취하고 축척은 인가 대지면적 기준값 유지 |
| `--sun-table` | 시각별 태양 위치·그림자 방위/길이와 주변 건물 방위각 출력 |
| `--sun-date` | `--sun-table` 기준일 (MM-DD, 기본 `12-22` 동지) |
| `--anchor-lat`, `--anchor-lon` | 대지 중심 위·경도(WGS84) |
| `--control-points` | 기준점 2점으로 축척·회전·위치 정밀 보정 (권장, 3절 참조) |
| `--no-context` | 주변 기존 건물 참고 레이어 생성 안 함 |

### 좌표 산정 방식

1. **축척**: 대지경계선 폴리곤의 픽셀 면적을 인가 대지면적 26,869.5㎡에 맞추어
   `m/px`를 자동 산정합니다(현재 0.23297 m/px). 배치도의 신설도로 20m,
   국제금융로7길 9m 폭과 교차 검증한 값입니다.
2. **회전·위치**: QGIS에서 실측한 기준점 2점으로 보정 완료되었습니다(아래 이력 참조).

### 위치 보정 이력 (적용 완료)

| 항목 | 보정 전(추정) | **보정 후(적용값)** |
| --- | ---: | ---: |
| 도면 상단 방위각 | 35.00° | **51.2051°** |
| 대지 중심 위도 | 37.5222 | **37.522129** |
| 대지 중심 경도 | 126.9291 | **126.933810** |

사용한 기준점 (EPSG:5186)

| 식별점 | 배치도 픽셀 | 실측 좌표 (E, N) |
| --- | ---: | ---: |
| 대지경계선 북서 코너 | `262,313` | `194114.76, 547091.16` |
| 대지경계선 북동 코너 | `1310,313` | `194272.85, 546894.50` |

두 점의 실거리는 252.32 m로, 픽셀거리 1048 px에 대해 축척 **0.24077 m/px**이 나옵니다.
이는 인가 대지면적 기준 축척(0.23297 m/px)보다 **3.35% 큽니다**. 원인은 대지경계선
코너의 **픽셀좌표 판독 오차**로 판단하여, 기본 산출물은 **축척을 인가 대지면적
기준값으로 고정**하고 회전·위치만 기준점에서 취했습니다(`--keep-area-scale`).
이때 두 코너의 잔차는 각각 **4.1 m**입니다.

기준점에 **완전 정합**시키려면 `--keep-area-scale` 없이 실행하십시오.
코너 오차는 0 m가 되지만 대지면적이 28,698㎡(+6.81%)로 커집니다.

```bash
# 기본 = 인가 대지면적 유지 (권장)
python3 daegyo_site_polygons.py

# 기준점 완전 정합 (대지면적 +6.81%)
python3 daegyo_site_polygons.py \
  --control-points "262,313,194114.76,547091.16;1310,313,194272.85,546894.50" \
  --outdir outputs/daegyo_cp_exact
```

## 3. 위치 정밀 보정 (필수 권장)

기본 앵커 좌표는 개략값이므로, 실제 지적/항공사진 기준으로 보정해야 합니다.
**기준점 2점만 찾으면 축척·회전·위치가 한 번에 맞춰집니다.**

### 3.0 기준점으로 쓸 배치도 식별점

```bash
python3 daegyo_site_polygons.py --list-reference-points
```

| 식별점 | 배치도 픽셀좌표 | 비고 |
| --- | ---: | --- |
| 대지경계선 북서 코너 | `262,313` | 국제금융로7길 남측선과 만나는 점 |
| 대지경계선 북동 코너 | `1310,313` | 동측 대로 서측선과 만나는 점 (권장) |
| 대지경계선 남동 코너 | `1310,770` | 신설도로(20m) 북측선과 만나는 점 (권장) |
| 대지경계선 남서 코너 | `178,770` | 서측 돌출부 남서단 |

> 두 점은 **가능한 한 멀리** 떨어진 조합(북서↔북동, 또는 북서↔남동)을 쓰십시오.
> 가까운 두 점을 쓰면 작은 판독 오차가 회전각으로 크게 증폭됩니다.

### 3.1 [방법 A] QGIS에서 좌표를 읽어 입력 — 가장 정확, 권장

1. **QGIS 프로젝트 CRS 설정**
   `Project → Properties → CRS` → `EPSG:5186` (Korea 2000 / Central Belt 2010) 선택
2. **배경지도 띄우기** (둘 중 하나)
   - *VWorld 항공영상*: `Browser` 패널 → `XYZ Tiles` 우클릭 → `New Connection`
     URL: `https://xdworld.vworld.kr/2d/Satellite/service/{z}/{x}/{y}.jpeg` (Max Zoom 19)
   - *연속지적도*: 국토정보플랫폼(map.ngii.go.kr) 또는 브이월드에서
     영등포구 여의도동 지적도 SHP를 내려받아 추가 → **지적선이 가장 정확합니다**
3. **대상 필지 찾기**: 여의도동 41 (국제금융로7길 20). 북측 국제금융로7길,
   남측 신설도로 예정구간, 서측 삼부아파트, 동측 대로로 둘러싸인 장방형 획지
4. **좌표 읽기**: 필지의 북서 코너에 마우스를 올리고 QGIS 하단 상태표시줄의
   `Coordinate` 값을 읽습니다. (표시 단위가 도(°)이면 상태표시줄 CRS가 4326이므로
   프로젝트 CRS를 5186으로 바꾸십시오.)
   - 더 정확히 하려면 `View → Toolbars → Snapping Toolbar`에서 스냅을 켜고
     `Identify Features` 또는 임시 포인트 레이어로 코너를 찍어 좌표를 확인합니다
5. **두 점 입력 후 재실행**

```bash
python3 daegyo_site_polygons.py \
  --control-points "262,313,<E1>,<N1>;1310,313,<E2>,<N2>"
```

여의도 일대의 EPSG:5186 좌표는 **E ≈ 193,000~194,000 / N ≈ 546,000~548,000** 범위입니다.
이 범위를 크게 벗어나면 좌표계를 잘못 읽은 것입니다.

### 3.2 [방법 B] 위·경도로 입력 — 간편

네이버/카카오/구글 지도에서 해당 지점을 우클릭해 위·경도를 읽어 그대로 넣습니다.

```bash
python3 daegyo_site_polygons.py --control-points-crs 4326 \
  --control-points "262,313,126.92730,37.52350;1310,313,126.92990,37.52210"
```

- 입력 순서는 `경도,위도`이지만, `위도,경도`로 넣어도 자동 판별해 교정합니다.
- 위·경도는 소수점 **5자리 이상**(약 1m 해상도)까지 읽어야 합니다.

### 3.3 [방법 C] 배치도 이미지를 직접 지오레퍼런싱

폴리곤이 아니라 **배치도 이미지 자체**를 QGIS에 깔고 싶을 때 씁니다.

1. `Raster → Georeferencer` 실행 → 배치도 이미지 열기
2. `Add Point`로 대지경계선 4개 코너를 찍고 각각의 EPSG:5186 좌표 입력
3. `Transformation type = Polynomial 1`(또는 Helmert), `Target SRS = EPSG:5186`
4. 변환 실행 후 생성된 GeoTIFF를 배경으로 깔고, 그 위에서 폴리곤을 직접 그리거나
   본 스크립트 결과와 겹쳐 검수

### 3.4 보정 결과 검증

재실행하면 리포트 상단에 기준점에서 **역산된 축척과 방위각**이 표시됩니다.

- 축척이 **0.233 m/px** 부근이어야 정상입니다 (대지면적 기준 산정값과 3% 이상
  차이나면 경고 문구가 출력됩니다)
- 방위각은 **51.2°** 부근(±3°)이 정상입니다 — 실측 보정된 값입니다
- `대지면적` 편차가 ±2% 이내인지 확인하십시오

검증 후 `outputs/daegyo/daegyo_buildings_wgs84.geojson`을 QGIS에 올려
위성영상과 겹쳐보면 최종 위치를 눈으로 확인할 수 있습니다.

### 3.5 값을 고정해 두기

매번 옵션을 넣기 번거로우면 `data/daegyo_site_plan.json` 의 `georeference` 항목
(`plan_up_azimuth_deg`, `anchor_lat`, `anchor_lon`)을 보정된 값으로 갱신하십시오.
리포트에 출력된 방위각을 `plan_up_azimuth_deg`에, 보정 후 대지 중심 위·경도를
앵커 값에 넣으면 이후에는 옵션 없이 실행해도 같은 결과가 나옵니다.

## 4. 출력 파일

| 파일 | 내용 |
| --- | --- |
| `daegyo_buildings_epsg5186.geojson` | **신축 건물(타워 12존 + 저층부 5블록)** – 분석 주 레이어 |
| `daegyo_buildings_wgs84.geojson` | 동일 데이터의 WGS84 버전(배경지도 확인용) |
| `daegyo_context_buildings_*.geojson` | 주변 기존 건물(삼부·장미·화랑·한양·여의도여고, 한양 재건축안) 참고 레이어 |
| `daegyo_site_boundary_*.geojson` | 대지경계선 |
| `daegyo_buildings.csv` / `.csvt` / `.prj` | WKT 포함 표 형식 (엑셀·타 프로그램 연계용) |
| `daegyo_trace_preview.svg` | 배치도 이미지와 동일 픽셀좌표계의 트레이싱 검수용 도면 |
| `daegyo_polygon_report.md` | 인가 제원 대비 검증 리포트 |

### 속성 스키마

| 필드 | 설명 |
| --- | --- |
| `id` | 존 식별자 (예: `101-A`) |
| `dong` / `part` | 동 명칭 / 존 구분 |
| `use` | 용도 (공동주택, 근린생활시설 등) |
| `floors` | 지상 층수 |
| `floor_h_m` | 층고 (주거 2.95m, 저층부 4.5m) |
| `roof_m` | 옥탑·파라펫 높이 (주동 4.0m) |
| `height_m` | **건물 높이(G.L. 기준)** = `floors × floor_h_m + roof_m` → 3D 돌출값 |
| `base_elev_m` | 계획 지반고 EL 13.3 m |
| `top_elev_m` | 최고고 (EL 기준) |
| `area_m2`, `gfa_m2` | 건축면적, 층수 환산 연면적 |
| `source` | 데이터 출처/정밀도 표기 |

### 높이 산정 규칙

```
height_m   = floors × floor_h_m + roof_m      # 지반면(G.L.)에서의 건물 높이
top_elev_m = base_elev_m + height_m           # 표고 기준 최고고
```

| 구분 | 층고 | 옥탑·파라펫 | 근거 |
| --- | ---: | ---: | --- |
| 공동주택 주동 | 2.95 m | 4.0 m | 초고층 아파트 표준 층고 + 옥탑 기계실/파라펫 |
| 저층부(근생·공공·주민공동) | 4.50 m | 0.0 m | 근린생활시설 일반 층고 |
| 지반고 | — | — | 배치도 남측 표기 `+13.3` → EL(+)13.3 m |

층고를 바꾸려면 `data/daegyo_site_plan.json` 의 `levels` 항목을 수정하십시오.
**건물별 상세 높이표는 실행 시 생성되는 `outputs/daegyo/daegyo_polygon_report.md`
에서 확인할 수 있습니다.**

## 5. QGIS에서 일조·그림자 분석하기

### 5.1 레이어 불러오기

- `Layer → Add Layer → Add Vector Layer`로 `daegyo_buildings_epsg5186.geojson` 추가
- 프로젝트 CRS를 **EPSG:5186**으로 설정 (`Project → Properties → CRS`)
- CSV를 쓸 경우 `Add Delimited Text Layer`에서 `wkt` 필드를 지오메트리로 지정

### 5.2 3D 그림자 (QGIS 내장 3D 맵뷰)

1. 레이어 속성 → `3D View` → `Single symbol`
2. `Extrusion` 을 필드값으로 지정: 식(Expression) 에 `"height_m"`
3. `Altitude clamping = Absolute`, `Altitude binding = Centroid`,
   지반고를 반영하려면 `Altitude` 에 `"base_elev_m"` 입력
4. `View → New 3D Map View` → 톱니바퀴 → `Shadows` 활성화
5. 태양 방위각·고도 입력

동지일(12/22) 서울(위도 37.52°N, 경도 126.93°E) 기준 태양 위치 – 남중시각 약 12:30 KST

| 시각(KST) | 태양 고도 | 태양 방위각(진북 기준) |
| ---: | ---: | ---: |
| 08:00 | 약 2.1° | 약 122° |
| 09:00 | 약 11.6° | 약 132° |
| 10:00 | 약 19.6° | 약 144° |
| 12:30 (남중) | 약 29.0° | 180° |
| 15:00 | 약 19.6° | 약 216° |
| 16:00 | 약 11.6° | 약 228° |

> 위 값은 적위 −23.44°, 균시차 약 +2분을 적용한 개략값입니다. 정밀 검토 시에는
> UMEP의 태양위치 계산이나 `pvlib` 등으로 시각별 값을 산출하십시오.

### 5.3 시간대별 그림자 폴리곤 자동 생성 (권장)

- 플러그인 **UMEP** → `Processing → Solar Radiation → Shadow Generator`
  - 입력: 건물 DSM(래스터). 아래 5.4로 폴리곤을 래스터화해 사용
- 또는 플러그인 **Shadow Analysis / Qgis2threejs**로 시각화

## 6. 정확도 한계 및 검수 체크리스트

이 데이터는 **래스터 배치도 이미지를 육안 트레이싱**한 결과이므로,
형상 정밀도는 **±2~3m 수준**이며 법적 검토용 성과품이 아닙니다.

- [ ] `daegyo_trace_preview.svg`를 원본 배치도 이미지 위에 100% 크기로 겹쳐 형상 확인
- [ ] `--control-points`로 지적도 기준 위치 보정 완료
- [ ] 최종 인가도면(배치도 CAD/PDF)으로 동별 층수·최고높이 재확인
- [ ] 지반고(EL 13.3m)와 실제 계획고 일치 여부 확인
- [ ] 주변 건물(`context`) 레이어는 개략값 → 실제 분석 시
      국가공간정보포털 **건물통합정보(GIS건물통합정보)** 또는 브이월드 3D 건물데이터로 대체
